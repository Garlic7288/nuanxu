结论：可以开公测

没有阻断性缺陷。核心链路（色温写入与还原、暂停计时、全局快捷键、开机自启、开窗尺寸、 安装与卸载）在装机版上逐项跑通。剩下的是「发布动作」而非「代码问题」——代码签名、 官网链接、发布说明这三件事需要先定下来，见第三节。

一、本轮修复的 10 个问题

按「用户会不会真的撞上」排序。前三条属于会真实损坏用户数据或体验的缺陷。

1启动后才插上的显示器，退出时会被抹掉校色仪校准

原始色彩快照只按显示器 ID 复用启动时那一份。中途插上的屏没有快照， 退出还原时退化成「线性表」——相当于把用户花钱做的硬件校准清掉了。 已修：写暖色前先补读原始表；没碰过的屏退出时直接跳过。

2暂停后「护眼本来关着」会被强行打开

用户做色彩校准、投屏时自己关了护眼，再按一次「暂停 30 分钟」，半小时后屏幕自己变暖， 还找不到原因。已修：护眼已关时拒绝暂停并给出说明，不再武装计时器。

3全屏放 PPT / 演讲时弹休息提醒

投影仪上突然弹出提醒框，是最尴尬的一类 bug。 已修：用系统通知状态判定全屏/演示模式，命中就把这次提醒顺延一个周期并记日志。

4完全没有运行日志，用户报障只能靠猜

已修：新增滚动日志 app.log（512KB 自动轮转，全程异常兜底， 绝不因为写日志把主流程带崩）。启动首行就带版本、构建时间、系统版本、屏幕缩放、显示器数量。

5诊断报告缺环境信息

原来的 diag.txt 只有显示器自检，看不出用户装的是哪一版、几块屏。 已修：头部补三行 [env]。

6Explorer 重启后托盘图标消失

资源管理器崩溃重启是常态，图标不回来，用户就以为程序退了。 已修：监听 TaskbarCreated 广播消息重新注册。

7缺 WebView2 时只报错、不给下载地址

已修：提示里直接给微软官方引导器链接，用户点一下就能装。

8托盘悬停提示不显示状态

原来只写「暖序 · 广州」，暂停中忘了、护眼关着都看不出来。 已修：改成「暖序 · 城市 · 状态」，四态为 跟随日光 / 固定暖度 / 暂停中 / 护眼已关。

9卸载后残留 1MB 陈旧日志

日志没在卸载清理清单里，目录也就一直挂着。 已修：卸载时连 .1 一起删；settings.json 按设计保留。

10README 还停留在原型阶段

原文还在推荐换 Tauri 重写，完全不像一个要给外人看的产品说明。 已重写：功能表、系统要求、无签名 SmartScreen 说明、隐私声明、 已知限制、诊断入口、命令行参数表。

三、建议公测前处理（需要你决策）

这三件不是代码问题，但会直接影响第一波用户的第一印象。

A代码签名 建议做

没有签名，用户双击安装包会先看到 SmartScreen 的「已保护你的电脑」红框， 点「更多信息 → 仍要运行」才能继续。公测阶段这是最大的一道流失门槛—— README 里已经写了说明，但真正点开 README 的人远少于被吓退的人。

OV 代码签名证书约 ¥1000–2000/年，能消掉 SmartScreen 警告（需积累一点信誉）； EV 证书（约 ¥3000+/年）即时生效但要走硬件令牌。若预算不允许，至少在下载页 放一张「会看到这个提示，这样点」的截图。

B安装包里的三个网址还是空的 公测前填

installer/暖序.iss 里 AppPublisherURL / AppSupportURL / AppUpdatesURL 仍是注释状态。 填上之后，用户在「控制面板 → 程序和功能」里点这个软件，就能直接跳到项目主页和帮助页—— 这是用户找不到人问时唯一的自助入口。

需要先确定三个地址（主页 / 帮助 / 更新日志）。目前留空，指向不存在的域名比不填更糟。

C发布说明里必须写清的版本号问题 发布时写

版本号从 1.8.4 改回 1.0.0 是重新编号，但装过旧版的用户会觉得这是降级， 「程序和功能」里显示的版本会从 1.8.4 变成 1.0.0。升级本身没问题（同一个安装标识， 会正常覆盖），但建议在发布说明里一句话交代：「版本号重新编号，1.0.0 是首个公测版， 功能上是 1.8.4 的延续」。

四、已知限制（建议原样写进发布说明）

这些是平台或驱动的边界，不是能修的 bug。提前说清楚，比让用户踩到再问要好。

  • HDR 模式下调色无效。Windows 不允许在 HDR 下改伽马表。程序会检测并弹提示， 需要用户关掉 HDR。
  • 部分显卡驱动 / 虚拟显示器 / 远程桌面会拒绝写入。同样会提示，不是程序坏了。
  • 混合 DPI 多显示器时副屏界面可能发虚。笔记本 150% + 外接屏 100% 的常见组合。
  • 界面上的暖度是调节强度，不是蓝光过滤百分比。没有仪器实测，不要写成「过滤 65% 蓝光」。
  • 休息提醒默认关闭。这是刻意的（护眼色温才是主功能，弹窗是打扰）， 但用户可能根本不知道有这个功能——建议在首次启动的引导或发布说明里提一句。
  • 没有自动更新。新版本要用户自己去下载重装。

五、本次审计未能覆盖的部分

如实说明，避免把「没测」当成「没问题」。

  • 多显示器真机。开发机只有 1 块屏，多屏路径只做了代码审查与跨 API 一致性验证， 没有双屏实机跑过。建议公测第一周重点收集双屏用户的反馈。
  • 「为所有用户安装」模式。需要管理员权限，本次只验了「仅为我安装」。
  • Windows 10。开发机是 Windows 11，Win10 1809 只在代码层面做了兼容处理， 没有实机验证。
  • 长期稳定性。连续运行数天后的内存与伽马表漂移未测。

六、暂不建议做的

  • 先放着 崩溃上报 / 埋点。和「无埋点无遥测」的隐私承诺冲突， 公测阶段靠用户主动发 app.log 足够。
  • 先放着 自动更新框架。引入的复杂度和风险大于收益， 等用户量起来再说。
  • 先放着 配置数据版本号。目前靠默认值兜底 + 城市别名迁移够用， 真正需要跨版本迁移时再加字段。
